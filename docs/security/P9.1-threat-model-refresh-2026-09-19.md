# P9.1 — Threat Model Refresh

**Date:** 2026-09-19
**Lane:** mh-14
**Baseline:** R4 ancestry preserved; refresh is additive evidence and does not change State Authority.

## Scope

Refresh of the repository threat model against the current security boundary implementation and existing deterministic security tests. Canonical authority remains State Authority; cloud, AI, plugins, adapters, credentials, diagnostics and recovery remain non-authoritative boundaries.

## Threat/control traceability

| Threat | Current control/evidence | State |
|---|---|---|
| Authority escalation / State Authority bypass | security boundary and state-authority red-team tests | COVERED
| Sandbox escape / filesystem boundary crossing | cloud sandbox escape and symlink tests | COVERED
| Unrestricted egress / endpoint misuse | egress allowlist and cloud adapter negative tests | COVERED
| Credential disclosure / broker misuse | CredentialBroker tests and native launcher isolation tests | COVERED
| Credential revocation / stale authorization | revocation/fail-closed tests in AI, adapter and policy paths | COVERED
| Malformed public contract input | adapter and security negative tests | COVERED
| Timeout/resource exhaustion | sandbox timeout/revocation tests | COVERED
| Plugin/AI/cloud confused deputy | provider wrapper and development security-boundary tests | COVERED
| Replay/idempotency across all protocol surfaces | architecture requirement; no universal protocol implementation evidence | REQUIRES VERIFICATION
| Concrete authentication/cryptographic protocol threats | technology-neutral architecture only | REQUIRES VERIFICATION
| Firmware/update supply-chain compromise | architecture controls documented; production qualification absent | REQUIRES VERIFICATION
| Physical/device topology compromise | architecture explicitly marks physical topology as unverified | REQUIRES VERIFICATION

## Residual release blockers

This refresh does not claim production qualification. Protocol-specific authentication, cryptography, replay/idempotency, firmware/update, physical topology and target-device controls remain evidence-gated. Any unresolved item above must remain a release blocker until implementation evidence and verification exist.

## Verification basis

The refresh is derived from the current `MH-12` security architecture, `MH-17` threat/security-testing contracts, and the repository security test inventory. No new authority, credential path, network path or runtime mutation path is introduced.
