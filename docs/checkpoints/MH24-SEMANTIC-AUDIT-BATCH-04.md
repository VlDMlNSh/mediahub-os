## 3. Cross-cutting findings

1. **Authority:** Media, documents, Twin, network integrations and external Smart Home systems must not become State Authority. MH-19 explicitly states that the Twin is a representation; physical change requires authorized command → device adapter → device → observation → Twin update.
2. **Capability, not blanket support:** Media codecs/endpoints, vendor network APIs, equipment adapters and product hardware need explicit capability qualification. A broad baseline category does not promise universal compatibility.
3. **OSS is a candidate until qualified:** PaddleOCR, FFmpeg/GStreamer/VLC, storage/search backends and other OSS choices require applicable licensing, security, provenance, benchmark, adapter and governance evidence; no specific component is declared adopted by this audit.
4. **Network extension is distinct evidence:** The 2026-09-30 network passport extension makes wired RJ45 upstream, seamless wireless coverage and Ubiquiti/Keenetic interoperability explicit requirements. It does not demonstrate a working controller, mesh, roaming or production network.
5. **Entitlements and product economics:** Digital Twin professional lock/unlock and one-time iPad Core payment are product/governance requirements; generic “entitlement” text alone does not prove enforcement or a finalized commercial decision.
6. **Status discipline:** MH-18/MH-19/MH-15/MH-17/MH-23 gates remain open/not accepted in the inspected refs. The matrix's section-level rows are not requirement-level evidence.

## 4. Semantic disposition

- **Preserved / broadly represented:** media as a separate non-authoritative domain; Documents OCR/search/provenance/workflows; Digital Twin as part of Full editions; qualification-led engineering/OSS adoption; network plane separation and seamless coverage outcome; discovery/qualification lifecycle; external Smart Home authority separation.
- **Candidate gaps needing explicit owner/governance decision:** exact media integration list; paid Document System entitlement; Twin runtime presence and professional lock enforcement; named engineering workflow scope; vendor-specific network-controller and roaming requirements; exact equipment onboarding/user confirmation UX; named Smart Home export targets and MPV Server; complete product edition catalogue and one-time mobile payment rule.
- **Unknown/not proven:** actual media/document/Twin/engineering runtime, vendor network integration, physical equipment discovery and onboarding, Smart Home export operation, edition-specific hardware qualification, license/entitlement enforcement and production status.

These findings are scoped to the listed refs and the literal/semantic comparison performed. They do not prove global absence elsewhere in GitHub or in an external runtime.
