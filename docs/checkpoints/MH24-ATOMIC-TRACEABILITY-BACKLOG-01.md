## 4. Closure protocol for each atomic item

An item may move from OPEN only when the record contains all applicable fields:
1. Exact B1 clause/anchor and source SHA.
2. B2 mapping or explicit `not represented / partial / conflict` disposition with exact clause/anchor and SHA.
3. Domain owner and decision: preserve / revise / defer / reject; rationale and approval provenance.
4. Canonical contract/ADR/acceptance criteria with exact path, ref and blob SHA.
5. Implementation artifact and source commit SHA, or explicit `NOT IMPLEMENTED`.
6. Required unit/integration/negative-path/security tests and exact run/artifact identifiers, or explicit `NOT RUN`.
7. Independent reviewer/qualification result, or explicit `NOT QUALIFIED`.
8. Any dependencies, privacy/safety implications, migration/rollback constraints and unresolved risks.
9. Read-back verification after each authorized document change; update project map only with confirmed refs and SHA.

Do not label an item “closed” merely because prose exists. A governance decision may close the semantic-disposition question while implementation/evidence/qualification remain open; track these as separate statuses.
