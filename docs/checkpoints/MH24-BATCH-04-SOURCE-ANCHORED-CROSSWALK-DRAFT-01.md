## 2. Status rules

- `MAPPED`: used only where the reviewed clause audit reports explicit B2 coverage for the historical atom without known partiality in that row. This is documentary mapping only, not implementation or qualification.
- `CONFLICT`: use only when an actual contradictory B1/B2 clause is cited. No such conflict is asserted by this draft because the reviewed records do not establish one for these 48 parents.
- `NO_DIRECT_COUNTERPART`: used only where the reviewed audit explicitly says the atom has no direct counterpart in the reviewed B2 clauses.
- `NOT_REVIEWED`: conservative default for partial, mixed, compound, cross-linked, derived, ambiguous or not-yet-individually-verified mappings. It does not mean “no mapping”.
- The parent-level status is intentionally conservative: one parent may contain several atoms with different eventual statuses. Before stable child IDs are assigned, each child atom must receive its own mapping status.
- All unverified values remain explicitly TBD/OPEN. Candidate B2 sections and branch-specific MH dependencies are leads, not accepted canonical contracts.
