# W04C — OpenRouter 403 remediation checkpoint

Date: 2026-09-10

## Objective

Remove OpenRouter from the native MediaHub Cloud Development Adapter execution path and prevent provider/geography failures from being misclassified as credential failures.

## Verified

- Native adapter providers are `codex` and `claude` only.
- Native launcher does not construct OpenRouter-bound commands.
- Credential Broker is the only credential source for native execution.
- Provider command argv is checked for unsafe modes and credentials are not placed in argv.
- Provider environment is bounded and credential-like variables are restricted.
- Native endpoint must be explicitly present in request and adapter egress allowlists.
- Full test suite: 300 passed.
- Ruff: all checks passed.
- ECC Codex agent definitions were repaired with required `name` and `description` metadata.

## Failure evidence

A real Codex invocation against `api.openai.com/v1/responses` returned HTTP 403 with the provider message `Country, region, or territory not supported` from the current server location. This is a provider geographic-policy response, not evidence of an invalid API key.

The system MUST NOT bypass provider regional restrictions using proxies, VPNs, location spoofing, or credential forwarding through an unapproved third-party service.

## Legacy OpenRouter boundary

Legacy OpenRouter gateway/lane artifacts remain only for compatibility/qualification history. They are not the native MediaHub authority path and must not be activated for production execution.

## Local development fallback

MediaHub local AI remains available on loopback. The current llama.cpp model exposes OpenAI-compatible HTTP endpoints. A Codex direct-local experiment was blocked by the model runtime's 4096-token context limit in the existing service; an isolated 8192-token process demonstrated the runtime can be started with a larger context, but persistent systemd modification requires authorized system-level service changes.

## Gate

Cloud provider execution remains fail-closed until an authorized, supported provider credential and endpoint are available. Local autonomous development remains the active development path.
