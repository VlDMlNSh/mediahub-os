# MH-09 — Emergency UI

**Status:** PROPOSED / REQUIRES VERIFICATION

Emergency presentation must be explicit, visible, auditable and fail-safe, with minimal dependence on AI, cloud or optional plugins.

Safety ordering is preserved: `Hard Safety > Manual Emergency > Explicit Admin Policy > Local Automation > Optimization > Recommendation`.

Emergency UI does not create authority. Any mutation still uses the authorized subsystem and canonical Consumer Boundary unless a separately accepted safety architecture explicitly defines another path.
